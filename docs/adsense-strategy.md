# 애드센스 승인 전략 (2026-10-01 정리)

다른 기기에서 이어서 작업하기 위한 기록입니다. 사실과 추측을 구분해서 적었습니다.

## 1. 현재 상태

- 반려 사유: **"가치가 별로 없는 콘텐츠"** (고유 가치, 지속적 운영, 실제 사용자 관심 세 가지를 요구)
- 3월부터 "승인 대비 수정, 재신청"을 5번 이상 반복했고, 매번 같은 결과였습니다.
- cloudplare.com의 Search Console (2026-10-01 확인):
  - 색인 약 10개, 검색 노출·클릭 0회
  - 404 72건, 리디렉션 3, 5xx 1, 표준 없는 중복 1
  - 발견됨-색인 안 됨 14, 크롤링됨-색인 안 됨 5
- 404 72건의 정체: 3~6월에 운영한 **복지 정보 사이트**의 `/policy`, `/service`, `/guide`, `/category` 경로입니다. 6월 12일에 CloudPlare 운영 노트로 바꾸면서 코드를 지웠지만 구글은 기억하고 있습니다.

## 2. 원인 진단

1. **글이 얇고 구조가 똑같습니다.** 본문 편당 약 1,000자, 섹션 3개, FAQ 2개, 코드 1개, 출처 2개로 거의 동일합니다.
2. **직접 겪은 경험이 없습니다.** 공식 문서를 재구성한 글이고 실제 출력, 캡처, 수치가 없습니다.
3. **사이트 이력이 불리합니다.** 복지 사이트 → 일반 가이드 → CloudPlare로 두 번 바뀌었고, 404가 새 글보다 많습니다.
4. **글 중심 사이트입니다.** 도구나 서비스가 없습니다. 승인된 레퍼런스는 모두 도구·데이터 중심입니다 (3번 참고).
5. 브랜드 이름이 Cloudflare와 혼동될 수 있습니다 (면책 문구는 넣어 둠).

## 3. 벤치마킹 (승인됐다고 알려진 사이트)

승인 소요 기간(2~3일) 등은 커뮤니티 글이라 검증하지 못했습니다. 생존자 편향 가능성이 있습니다.

| | wawaedu.co.kr | powerblog.net |
|---|---|---|
| 핵심 | 전국 학원 138,566곳 교습비 실데이터 조회 | 계산기·도구 71개 (세금, 급여, 대출, 건강, 행정 가이드) |
| 세부 페이지 | 약 1,800개. 지역별 평균·중앙값·분포·운영 연수를 **직접 계산**해서 표시 | 도구마다 독립 페이지 |
| 글 | 교육 가이드 68편 (실데이터 분석 기반) | blog, faq는 보조 |
| 신뢰 페이지 | 소개(출처·이용조건·갱신 주기), 이미지 출처, 면책 | about, contact, privacy, terms, faq, sitemap |

**공통 패턴**
1. 주제가 하나입니다.
2. 글이 아니라 **도구가 중심**이고 사용자가 입력하면 결과가 나옵니다.
3. 공식 문서를 다시 쓴 글로는 만들 수 없는 **고유 계산 결과**가 있습니다.
4. 출처와 갱신 주기를 투명하게 밝힙니다.

## 4. 결정한 방향

- **이 사이트(cloudplare.com)에서 승인받는 것은 포기합니다.** 재신청은 당분간 중단합니다. 인터뷰 답을 받아 대표 글만 보강하는 정도로 유지합니다.
- **새 도메인에서 도구 중심 사이트를 새로 만들어 신청합니다.**
- 기존 `zucca100.com` 계열은 고려하지 않습니다 (사용자 결정).
- 도메인 구매는 **컨셉이 확정된 뒤** 마지막에 합니다. 구매 전 Wayback Machine으로 과거 이력을 확인합니다.

### 추천안의 설계
- **계산기 8~10개**: 증여세, 상속세, 증여세 면제한도, 취득세 등 한 주제 안에서만 만듭니다. 71개를 늘어놓지 않습니다.
- **시나리오별 결과 페이지**: "자녀 증여 1억/3억/5억 세금" 같은 표를 직접 계산해서 보여 줍니다. 이게 wawaedu의 지역 통계에 해당하는 고유 데이터입니다.
- **가이드 15~20편**: 직접 계산한 사례 중심입니다. 공식 문서를 풀어 쓰는 글은 피합니다.
- **필수 페이지**: 소개(근거 법령, 계산 기준일, 갱신 주기), 문의, 개인정보, 약관, FAQ, 출처, sitemap
- **위험 관리**: 국세청·법령의 공식 계산 방식만 쓰고 기준 시행일을 화면에 표시합니다. 국세청 예시 사례를 테스트 케이스로 검증합니다. 면책 문구와 세무사 상담 안내를 넣습니다.

## 6. 진행 순서

1. 컨셉 확정 (위 후보 중 선택)
2. 도메인 후보 선정 기준 잡기, 구매 (Wayback으로 이력 확인)

**원칙**: 승인용으로 고치는 루프에 다시 들어가지 않습니다. 쓸 수 있는 도구를 먼저 만들고 신청합니다.
